# Как выложить SYNCORE calc на syncore54.ru

Схема та же, что у портфолио [pavelislamov.ru](https://pavelislamov.ru/): **файлы лежат на GitHub Pages**, **домен крутится в Beget** (там только DNS). Репозиторий уже создан: [github.com/pavelislamov-gif/syncore-calc](https://github.com/pavelislamov-gif/syncore-calc).

Делайте шаги **по порядку**. Не пропускайте DNS: без него сайт на GitHub откроется, а `syncore54.ru` — нет.

---

## Что не нужно делать

- Не создавайте сайт `syncore54.ru` в Beget → **Сайты** и не «прикрепляйте домен» к хостингу. Панель пропишет IP Beget вместо GitHub — Pages сломается.
- Не заказывайте SSL в Beget для этого домена. Сертификат выдаст GitHub.
- Не заливайте исходники в `public_html`. На Pages уходит готовая сборка из GitHub Actions.
- Пароль от GitHub в `git push` не подходит. Нужен **токен**.

---

## Шаг 1. Токен GitHub (один раз)

1. Откройте [github.com/settings/tokens](https://github.com/settings/tokens) (войдите как **pavelislamov-gif**).
2. **Generate new token** → **Generate new token (classic)**.
3. Note: `syncore-calc push`.
4. Expiration: 90 days или больше.
5. Галочки:
   - `repo` (весь блок)
   - `workflow`
6. **Generate token**. Скопируйте строку `ghp_…` сразу: второй раз GitHub её не покажет. Никому не отправляйте.

---

## Шаг 2. Залить код в репозиторий

Это не в чате с агентом и не на сайте GitHub. Нужно **приложение Cursor на вашем компьютере**, открытый проект калькулятора (слева в списке файлов виден `package.json`).

Команды ниже — просто **скопировать и нажать Enter**. Разбирать их не обязательно.

### 2.1. Откройте чёрное окно (терминал)

1. В Cursor нажмите **Ctrl+`** (клавиша Ё / тильда, слева от 1)  
   или меню **Terminal → New Terminal**.
2. Внизу появится строка. В её начале должен быть путь к проекту. Если написано `package.json: command not found` — вы не в той папке: напишите `ls` (Mac/Linux) или `dir` (Windows) и убедитесь, что в списке есть `package.json`.

### 2.2. Первая команда — «куда отправлять»

Скопируйте **целиком** одну строку, вставьте в терминал, Enter:

```bash
git remote add github https://github.com/pavelislamov-gif/syncore-calc.git
```

Что произошло: компьютеру сказали адрес вашего пустого репозитория.

- Если **ничего не написало** и снова мигает курсор — хорошо, идите к 2.3.
- Если `remote github already exists` — тоже хорошо, эту команду больше не повторяйте, сразу 2.3.
- Если `not a git repository` — проект открыт не та папка. File → Open Folder, выберите папку, где лежит `package.json`.

### 2.3. Вторая команда — «отправь файлы»

```bash
git push -u github HEAD:main
```

Может спросить:

```
Username for 'https://github.com':
```

Напишите `pavelislamov-gif` и Enter.

```
Password for 'https://github.com':
```

**Вставьте токен** `ghp_…` (из шага 1) и Enter. Буквы при вводе **не отображаются** — так и задумано, не думайте, что поле пустое.

Успех выглядит примерно так: `main -> main` или `new branch`. Тогда откройте [github.com/pavelislamov-gif/syncore-calc](https://github.com/pavelislamov-gif/syncore-calc) и обновите страницу: должны появиться папки `src`, `public`, файл `package.json`.

### Если вместо успеха красный текст

**`rejected` / `failed to push` / `non-fast-forward`** — на GitHub уже лежит README. Тогда одна команда:

```bash
git push -u github HEAD:main --force
```

Она затирает только репозиторий **syncore-calc**, не портфолио.

**`Authentication failed` / `403`** — ввели пароль от сайта вместо токена. Снова шаг 1, новый токен, снова 2.3.

**`could not read Username`** — терминал в Cursor не умеет спросить логин. Тогда вставьте токен прямо в адрес (токен никому не пересылайте и не коммитьте):

```bash
git push -u https://pavelislamov-gif:СЮДА_ВСТАВИТЬ_ТОКЕН@github.com/pavelislamov-gif/syncore-calc.git HEAD:main
```

После удачного push эту строку из истории терминала лучше не копировать в чаты.

## Шаг 3. Включить GitHub Pages

1. Откройте [настройки Pages](https://github.com/pavelislamov-gif/syncore-calc/settings/pages).
2. **Build and deployment → Source:** GitHub Actions (не «Deploy from a branch»).
3. **Custom domain:** введите `syncore54.ru` → **Save**.
4. Пока DNS не настроен, будет жёлтое «DNS check unsuccessful» — это нормально, переходите к шагу 4.
5. Вкладка **Actions** репозитория: workflow **Deploy GitHub Pages** должен быть зелёным. Если красный — откройте лог; чаще всего не хватило права `workflow` у токена при первом push файла `.github/workflows/`. Тогда снова `git push` с токеном, у которого стоит `workflow`.

**Enforce HTTPS** не включайте, пока GitHub не напишет, что домен проверен (часто через 10–60 минут после DNS, иногда до 24 часов).

---

## Шаг 4. DNS в Beget

1. Войдите в [панель Beget](https://cp.beget.com/).
2. **Домены** (не «Сайты») → домен **syncore54.ru** → DNS-записи / управление зоной.
3. Удалите у `@` старые **A** и **AAAA**, если они указывают на IP Beget (цифры не `185.199.…`).
4. Добавьте **четыре** записи A для имени `@` (или пустое имя — это сам `syncore54.ru`):

| Имя | Тип | Значение |
| --- | --- | --- |
| `@` | A | `185.199.108.153` |
| `@` | A | `185.199.109.153` |
| `@` | A | `185.199.110.153` |
| `@` | A | `185.199.111.153` |

5. Для `www`:

| Имя | Тип | Значение |
| --- | --- | --- |
| `www` | CNAME | `pavelislamov-gif.github.io.` |

Точка в конце у CNAME в панели Beget иногда ставится сама — если сохраняется без точки, оставьте как принимает форма.

6. Сохраните. Подождите 10–60 минут (редко до суток).

Проверка с компьютера:

```bash
nslookup syncore54.ru
```

Должны быть адреса `185.199.108–111.153`, как у портфолио.

---

## Шаг 5. HTTPS и финальная проверка

1. Снова [Pages](https://github.com/pavelislamov-gif/syncore-calc/settings/pages): дождитесь галочки у домена, включите **Enforce HTTPS**.
2. Откройте:
   - https://syncore54.ru
   - https://syncore54.ru/milling
   - https://www.syncore54.ru (должен открыться тот же сайт)

Если главная есть, а `/milling` даёт 404 от GitHub — не прошла сборка или нет `404.html`. Зайдите в **Actions**, перезапустите последний успешный workflow, подождите 1–2 минуты.

## Если что-то пошло не так

| Симптом | Что сделать |
| --- | --- |
| `git push` просит пароль и отклоняет | Вставляйте токен `ghp_…`, не пароль GitHub. |
| `remote github already exists` | `git remote set-url github https://github.com/pavelislamov-gif/syncore-calc.git` и снова push. |
| Actions красный на `pages.yml` | Токен без права `workflow`; или в Pages Source не GitHub Actions. |
| `syncore54.ru` открывает заглушку Beget | Домен прикреплён к «Сайту». Открепите, верните A-записи GitHub. |
| Домен открывает чужой GitHub Pages | В репозитории должен быть файл `CNAME` с одной строкой `syncore54.ru`, в Pages указан тот же домен. |
| Нет замочка HTTPS | Сначала зелёный DNS check в Pages, потом Enforce HTTPS. |
| Старая версия сайта | Жёсткое обновление (Ctrl+F5). Проверьте, что Actions задеплоил новый коммит. |

Счётчик посещений `/usage` на GitHub Pages **не работает** (нет серверного API). Для прод нужен отдельный сборщик (Plausible, Umami).

---

## Обновления сайта потом

Меняете код → коммит → `git push github HEAD:main` (или Push в Cursor/Desktop). Actions сам соберёт и выложит на `syncore54.ru` за одну-две минуты.
